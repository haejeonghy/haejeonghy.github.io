## 1. 코루틴을 처음 설명할 때 가장 먼저 부딪히는 문제

코루틴을 처음 배우면 보통 이런 순서로 헷갈린다.

- 코루틴이 그냥 스레드인가
- 서브루틴과 뭐가 다른가
- 가상 스레드나 고루틴과 비슷한 건가
- Kotlin의 `suspend`, `Job`, `async`, `await`는 각각 뭘 하는가

이 글은 이 질문들을 한 흐름으로 정리한 기록이다.

## 2. 먼저 서브루틴부터 잡아야 한다

일반 함수, 즉 서브루틴은 호출되면 내부 코드를 끝까지 실행한 뒤에야 호출한 쪽으로 돌아온다.

카페 예시로 보면:

- 라떼를 만든다
- 에스프레소를 추출한다
- 우유를 데운다
- 컵에 따른다
- 완성 후에야 제어가 돌아온다

즉 서브루틴의 핵심은:

- 호출되면 끝까지 실행
- 중간 상태를 호출자에게 넘긴 채 잠깐 멈췄다가 다시 이어가는 모델은 아님

## 3. 코루틴은 중간에 멈췄다가 다시 이어갈 수 있다

코루틴은 "함수처럼 보이지만, 중간에 잠깐 제어를 양보하고 나중에 이어서 실행할 수 있는 흐름"으로 이해하면 된다.

카페 비유로 보면:

- 에스프레소를 추출한다
- 잠깐 멈춘다
- 손님 질문을 응대한다
- 다시 돌아와 우유를 데운다
- 또 멈출 수 있다
- 나중에 이어서 컵에 따른다

즉 차이는 이렇다.

- 서브루틴
  끝까지 실행하고 복귀
- 코루틴
  중간에 멈추고, 다시 이어서 재개 가능

코틀린에서는 이 감각을 `sequence { yield(...) }` 같은 간단한 예제로도 느낄 수 있고, 본격적으로는 `suspend` 함수와 코루틴 빌더로 다루게 된다.

## 4. 스레드는 또 다른 이야기다

코루틴을 이해할 때 스레드와 꼭 구분해야 한다.

스레드는 독립된 실행 흐름이다.

카페 비유로 보면:

- 서브루틴
  바리스타 한 명이 음료를 끝까지 만들고 돌아옴
- 코루틴
  바리스타 한 명이 작업을 하다가 잠깐 멈췄다가 다시 이어감
- 스레드
  바리스타 한 명이 더 생겨서 동시에 다른 작업을 함

즉 스레드는 "동시에 돌아가는 실행 단위"에 가깝고, 코루틴은 "중간에 멈추고 재개 가능한 작업 흐름"에 더 가깝다.

## 5. 가상 스레드는 일반 스레드와 무엇이 다른가

가상 스레드는 스레드 API를 유지하면서 훨씬 가볍게 만든 실행 단위다.

둘 다 코드 사용감은 비슷하다.

- 둘 다 `start()` 할 수 있다
- 둘 다 독립된 실행 흐름처럼 다룬다
- 둘 다 blocking 코드도 실행할 수 있다

하지만 차이는 비용과 스케줄링 방식에 있다.

- 일반 스레드
  OS 스레드와 강하게 연결되고, 많이 만들수록 비용이 커진다
- 가상 스레드
  JVM이 매우 가볍게 많이 만들 수 있도록 관리한다

그래서 가상 스레드는 특히 I/O 대기가 많은 서버 작업에 잘 맞는다.

## 6. 고루틴과는 비슷하지만 같은 것은 아니다

고루틴과 가상 스레드는 어느 정도 비슷해 보인다.

- 둘 다 가볍다
- 둘 다 많은 동시 작업을 다루기 좋다

하지만 철학은 다르다.

- 고루틴
  Go 언어와 런타임이 함께 제공하는 동시성 모델
- 가상 스레드
  Java의 기존 스레드 모델을 훨씬 가볍게 확장한 것

즉:

- 고루틴은 "언어 차원의 동시성 모델"
- 가상 스레드는 "더 가벼운 스레드"

에 가깝다.

## 7. 속도 개선을 위해 동시에 여러 작업을 돌리면 무조건 가상 스레드가 좋은가

그렇지는 않다. 먼저 작업이 어떤 종류인지 봐야 한다.

### 7.1 I/O bound 작업

- DB 호출
- HTTP 호출
- 파일 읽기/쓰기

이런 작업은 기다리는 시간이 많다.  
가상 스레드는 이런 대기 시간을 많이 겹쳐 처리하기 좋다.

### 7.2 CPU bound 작업

- 대량 계산
- 이미지 처리
- 암호화

이런 작업은 CPU를 계속 써야 하므로, 가상 스레드를 많이 만든다고 무조건 빨라지지 않는다.

즉:

- 느린 이유가 대기면 가상 스레드가 유리할 수 있다
- 느린 이유가 계산이면 병렬 처리 전략 자체를 따로 설계해야 한다

## 8. Kotlin으로 오면 `suspend`를 먼저 이해해야 한다

코틀린 코루틴에서 `suspend`는 중단 가능한 함수를 뜻한다.

예를 들어 카페라떼를 만드는 과정을 이렇게 쪼갤 수 있다.

```kotlin
suspend fun grindBeans() { ... }
suspend fun brewEspresso() { ... }
suspend fun steamMilk() { ... }
```

그리고:

```kotlin
suspend fun makeCafeLatte() {
    grindBeans()
    brewEspresso()
    steamMilk()
}
```

이렇게 읽으면 된다.

- 코드 모습은 일반 함수 호출처럼 순차적이다
- 하지만 중간에 중단 가능한 지점이 있다
- 스레드를 막지 않고 나중에 이어서 실행할 수 있다

즉 `suspend`는 "코루틴 안에서 중단 가능한 작업 단계"라고 이해하면 된다.

## 9. `Job`은 실행 중인 코루틴 작업표다

`launch { ... }`를 호출하면 `Job`을 받는다.

```kotlin
val job: Job = launch {
    makeCafeLatte()
}
```

`Job`은 결과값이 없는 작업 자체를 가리키는 핸들이다.

그래서 할 수 있는 일은:

- `job.join()`
  작업이 끝날 때까지 기다리기
- `job.cancel()`
  작업 취소하기
- `job.cancelAndJoin()`
  취소하고 종료까지 기다리기

카페 비유로 보면:

- `Job`
  "이 주문 제조 작업"을 가리키는 추적표

## 10. `async`와 `await`는 결과값이 있는 작업이다

`launch`는 결과값 없는 작업 실행에 가깝다.  
반면 `async`는 결과값을 돌려받고 싶을 때 쓴다.

```kotlin
val priceDeferred: Deferred<Int> = async {
    calculateDrinkPrice("카페라떼", 5500)
}

val price = priceDeferred.await()
```

즉:

- `launch`
  `Job` 반환
- `async`
  `Deferred<T>` 반환

여기서 `Deferred<T>`는 "결과를 나중에 받을 수 있는 `Job`"처럼 보면 된다.

카페 비유로 말하면:

- `Job`
  음료 제조 작업표
- `Deferred<Int>`
  가격 계산 작업표
  끝나면 결과값도 돌려준다

## 11. `coroutineScope`는 자식 코루틴을 한 범위로 묶는다

실무에서 자주 나오는 이유는 한 작업 안에서 여러 하위 작업을 동시에 실행하고, 그들이 전부 끝날 때까지 함께 관리하고 싶기 때문이다.

예를 들어:

- 에스프레소 샷 준비
- 스팀 우유 준비

이 둘을 동시에 시작할 수 있다.

```kotlin
suspend fun prepareCafeOrder() = coroutineScope {
    val espressoShot = async { ... }
    val steamedMilk = async { ... }

    val completedDrink = "${espressoShot.await()} + ${steamedMilk.await()}"
}
```

핵심은:

- 이 범위 안의 자식 코루틴들이 다 끝나야 밖으로 나간다
- 한 작업 묶음을 안전하게 관리할 수 있다

## 12. `withContext(Dispatchers.IO)`는 작업 성격에 맞는 실행 문맥으로 보낸다

코틀린 코루틴에서는 작업 종류에 따라 적절한 디스패처로 보내는 일이 중요하다.

예를 들어 파일 읽기, 네트워크 호출 같은 I/O 작업은 보통 이렇게 감싼다.

```kotlin
suspend fun loadTodayBeansFromFile(): String = withContext(Dispatchers.IO) {
    ...
}
```

이건 "이 블록은 I/O 성격의 작업이니 그에 맞는 문맥에서 실행하자"는 의미다.

즉:

- `coroutineScope`
  작업 범위를 관리
- `withContext`
  작업이 실행될 문맥을 전환

로 읽으면 된다.

## 13. 정리하면서 다시 비교하기

헷갈리기 쉬운 개념들을 한 줄씩 다시 줄이면 이렇다.

- 서브루틴
  호출되면 끝까지 실행 후 복귀
- 코루틴
  중간에 멈추고 재개 가능한 작업 흐름
- 스레드
  독립된 실행 흐름
- 가상 스레드
  스레드처럼 쓰지만 훨씬 가벼운 실행 단위
- 고루틴
  Go식 경량 동시성 실행 단위
- `suspend`
  중단 가능한 함수
- `Job`
  결과 없는 코루틴 작업 핸들
- `Deferred<T>`
  결과를 나중에 받을 수 있는 코루틴 작업 핸들
- `coroutineScope`
  자식 코루틴을 하나의 범위로 묶기
- `withContext`
  작업 실행 문맥 바꾸기

## 14. 마무리

처음에는 코루틴을 "스레드 비슷한 것"으로 이해하기 쉽다.  
완전히 틀린 방향은 아니지만, 그렇게만 보면 `suspend`, `Job`, `Deferred`, `coroutineScope`, `withContext`가 왜 필요한지 잘 안 보인다.

오히려 이렇게 이해하는 편이 더 정확했다.

- 스레드는 실행 단위다
- 코루틴은 중단과 재개가 가능한 작업 흐름이다
- Kotlin 코루틴 API는 그 흐름을 구조적으로 관리하기 위한 도구들이다

그래서 코루틴을 처음 공부할 때는, "스레드보다 가벼운가"보다 먼저 "어떻게 멈추고, 어떻게 기다리고, 어떻게 결과를 받고, 어떻게 범위를 관리하는가"를 보는 편이 더 도움이 된다.
